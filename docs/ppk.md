# PPK

GUI の「処理設定」で GNSS を「PPKを計算して使う」にすると、軌跡の最適化の前に、`BASE.BIN`（基準局、RTCM3）と `ROVER_PPKRAW.bin`（ローバー、Unicore）から、前方解と後方解を統合した PPK 測位を行います。時刻を合わせるため、生データの `info/*.bag` の同期情報（`/ssync/sync_time`）も必要です。

測位エンジン（RTKLIB demo5）は内蔵しており、外部アプリや追加の DLL は要りません。出典と変更点は [crates/s20-ppk/README.md](../crates/s20-ppk/README.md) にあります。

- 結果は `runs/ppk.json` に保存し、ループや除外区間を直して最適化し直すときは再利用します。
- PPK を使う場合も LIO は先に実行するので、早い段階で着色前の点群を確認できます。
- PPK と機体の RTK は、選んだ一方だけを使います。「GNSS を使わない区間」は両方に適用します。

```
s20 run <生データ> <作業フォルダー> --outdoor --ppk
s20 ppk <生データ> runs/ppk.json
s20 opt <data> runs/lio.txt runs/opt.txt --ppk runs/ppk.json
```

## 採用の条件

- 既定では、推定誤差が水平 10 cm・鉛直 20 cm 以下の FIX だけを採用し、各点の推定誤差を最適化の重みにします。
- FLOAT も使う場合は詳細パラメータで有効にします。水平 20 cm・鉛直 40 cm の誤差の下限で、拘束を弱めます。
- 採用できる点が足りない場合は、理由を表示して止まります。
- PPK でも、遮蔽やマルチパスで途切れた区間が必ず FIX に戻るわけではありません。

## 前方解と後方解の照合

前方解と後方解の位置を、東・北・上ごとに 4σ で照合します。σ には水平 1 cm・鉛直 2 cm の下限を設けます（`fix_check_sd_h`／`fix_check_sd_v`）。FIX の推定誤差は数 mm と小さめに出ますが、正しい FIX 同士でも 1〜2 cm 違うためです。

- 両方 FIX で食い違えば、FLOAT に落とします。
- 一方だけ FIX の場合は、相手の FLOAT 解と食い違えば、その差を推定誤差に加え、採用の条件で判断します。

生データの確認画面（「ツール」→「生データを見る…」→「GNSS」）では、FIX を「FIX」（両方 FIX）、「片方向 FIX」（片方だけ FIX で、もう片方の解と近く、最適化で使うもの）、「FIX（不採用）」に分けて表示します。

## 高さ

高さは楕円体高です。基準局のアンテナ高やジオイド高を二重に足すことはしません。最適化は、現場付近を原点とするローカル ENU（東・北・上、m）で行います（[処理の仕組み](processing.md#座標系)）。

## オプション

GUI でも同じ項目を変更できます。

| オプション | 既定 | |
|---|---|---|
| `--interval` | 0.1 | 測位の間隔（秒） |
| `--elevation` | 15 | 仰角マスク（度） |
| `--ar_ratio` | 3 | AR の ratio の閾値 |
| `--frequencies` | 3 | 使う周波数の数 |
| `--systems` | gps,glo,gal,bds,qzs | 使う衛星システム |
| `--estimate_ionosphere`、`--estimate_troposphere` | 無効 | 電離層・対流圏の推定 |
| `--use_float` | 無効 | FLOAT も使う |
| `--max_sd_h`、`--max_sd_v` | 0.10、0.20 | 採用する推定誤差の上限（m） |
| `--fix_check_sd_h`、`--fix_check_sd_v` | 0.01、0.02 | 前方解と後方解の照合の σ の下限（m） |
| `--phase_snr_error` | 0 | 信号強度による重み付け（比較用） |
| `--prefer_base_l2c` | 無効 | 基準局の GPS L2C を優先（比較用） |

エンジンを更新したときは、測位のキャッシュと、PPK を使った最適化の結果を計算し直します。
